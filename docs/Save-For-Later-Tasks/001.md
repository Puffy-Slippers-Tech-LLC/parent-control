# Define how requests and results travel between the app and broker

Acceptance: review

Prerequisite is the settled [feature design](../Save-For-Later-Design.md) and
its recorded [native qualification](../Save-For-Later-Design.md#native-qualification-gate).

Record the exact additive D-Bus signatures and caller matrix in the design's
[backend contract](../Save-For-Later-Design.md#shared-backend-and-authorization).
Use the live [broker interface](../SystemDesign/Broker.md#broker-interface-and-roles),
both introspection definitions, and the current request and Parent clients.
Specify types/bounds, field names and optional estimates, evaluation time and
revision semantics, typed unavailable/busy/stale/recovery results, and the
committed-saved-with-pause-error result. Define how a read during account
invalidation suppresses the record while the serialized writer clears it.

Review the contract against kiosk, same-child, unrelated caller and
administrator access, plus signed-in session requirements for new mutations.
Check old immediate/status clients against the new broker and new clients
against an older broker. There must be an explicit result for any unavailable
value and for obtaining fresh status after a lost reply. Keep authorization
derived from bus credentials and preserve the old method shapes.

Deliver the reviewed contract in the design and check its Markdown links.
Keep product code, runtime inventories, and native qualification out of this
task. No runtime resources are needed.
