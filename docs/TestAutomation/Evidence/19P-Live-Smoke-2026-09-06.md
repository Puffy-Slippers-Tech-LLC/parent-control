## Implemented boundary

`check_graphical_smoke.py` is a fixed no-argument dispatcher check. It pins tool
versions, records integration/distribution source digests, loads the schedule
before acquiring the lease, reuses observation-only offline SSH bootstrap,
and starts the existing worker with a copied distribution. It creates no
additional VM, overlay or snapshot and installs no product package. Its
`generalhw` variables use the existing private lifecycle callbacks and namespace
VNC bridge. Worker closure precedes callback closure and outer lease cleanup.

The distribution uses public [test APIs](https://github.com/os-autoinst/os-autoinst/blob/b85e4864/testapi.pm)
to capture GDM, click the top-right menu and dismiss it with Escape, requiring
both screen changes. Fixed local stage files synchronize with guarded SSH
observations of the active greeter and absence of logged-in user sessions.
Session identifiers stay inside the guest observation process. Screen headers,
dimensions, digest changes, complete stages and an `ok` module result are
required. Pixel/semantic review and safe screen export remain unfinished.
Raw backend output, screenshots, keys and vars stay root-private; summary
metadata is not a claim that private images have been redacted. No credentials
are entered; serial and video capture are disabled.

The initial distribution called `set_distribution` without its namespace;
`use testapi` does not export it. The supported call is
`testapi::set_distribution`. Perl `-c` did not catch this runtime loader error.
The new preflight uses the documented
[`_EXIT_AFTER_SCHEDULE=1` option](https://github.com/os-autoinst/os-autoinst/blob/b85e4864/doc/backend_vars.asciidoc).
In this pinned version, the CLI's END block overrides the early exit status
with its initial value 1. Preflight therefore requires the exact successful
schedule and early-exit diagnostics as well as status 0/1; ordinary compilation
failures remain failures. The live command uses `--exit-status-from-test-results`
and independently rejects failed/soft-failed module evidence.

No host package, AppArmor policy, product service, or application data schema
changed. Test helpers activate on next invocation (`none`). Existing host tool
pins remain in `setup.sh`; no new host dependency was needed.

## Recovery and verification

Connection loss exposed a missing recovery path. The new fixed
`check_graphical_recovery.py` accepts only the root-owned `cleanup-requested`
journal with its exact still-running VNC domain identity. It reacquires the
exclusive lock and verifies the finalized baseline digest, original layout,
run marker, domain ID, source layout and snapshot/backing proof before calling
ordinary `Lease.finish()`. Other phases, off/replaced domains and changed
identities are refused. It never starts/provisions a guest or recreates a
baseline, and never rewrites the original failed result.
