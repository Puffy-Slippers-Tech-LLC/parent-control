# Keep saved time through upgrades and clear it on removal

Acceptance: host

Prerequisite is 002. Use the design's [package lifecycle rules](../Save-For-Later-Design.md#app-policy-revocation-and-other-lifecycle-operations),
the [removal contract](../SystemDesign/Package-Removal.md#remove-purge-and-retry),
the [migration order](../SystemDesign/Data-Migration.md#package-lifecycle),
and the [activation classifier](../SystemDesign/Lifecycle.md#package-activation-and-session-renewal).

Wire the grant directory and migration into the shipped source and native
DEB/RPM provisioning and cleanup routes. Invalidate records at the point where
successful removal retires rollback material. Preserve records while removal can
be aborted, delete the store on purge, and preserve valid records and intents
across upgrades. Use existing broker/frontend restart and reload classifications.
This task owns packaging hooks and host checks. The installed histories are
owned by 015 and 016.

Exercise the affected package hooks, activation and native removal contracts
with maintained host fixtures, including aborted removal, interrupted
finalization, reinstall after completed removal, and preservation of ordinary
preferences. Build via the queued builder after the final packaging edit.
Use private staging and its normal cleanup route.
