# Store saved time securely for each child

Acceptance: host

Prerequisite is 001. Use the [store design](../Save-For-Later-Design.md#persistent-state-and-recoverable-transactions),
[account binding](../Save-For-Later-Design.md#account-binding),
[state ownership](../SystemDesign/State.md), and
[migration contract](../SystemDesign/Data-Migration.md).

Implement the broker-private per-UID store, format validation, atomic writes,
and a separate pure JSON migration pass in the existing state migration
registry. Represent both intent formats, the last fixed tuple/ended marker,
and a saved balance with its own app choice. Store reads distinguish absent,
invalid account, unsupported/corrupt data, and a valid empty balance. Supply
the invalidation operation for serialized callers and maintain revision
semantics across record updates and clear operations. Retain the existing
service sandbox. Transition decisions and package removal hooks belong to
later tasks.

Use focused storage and migration unit checks for mode/ownership, symlinks and
non-regular files, duplicate keys, invalid bounds, malformed/future formats,
account changes, and interrupted atomic replacement/migration. Verify
independent children and that no identity or reusable authorization enters
diagnostics. Use the queued package check for shipped changes and release
owned fixtures and build allocations under their normal lifecycle.
