## Implemented and observed

`tests/integration/system_remote_accounts.py` provisions an OpenLDAP directory
and SSSD NSS provider through supported package/configuration interfaces. It
runs only after the guest identity guard, refuses configuration/identity
collisions, and uses root's SASL EXTERNAL peer credentials for directory
administration. LDAP identity queries stay on guest loopback. It creates no
local passwd entries and edits no private AccountsService records. NSS
enumeration and lookup must resolve both directory identities before public
AccountsService `CacheUser` calls. Baseline restoration owns fixture cleanup.

The registered `test_remote_accounts_are_excluded` proves both standard and
administrator directory identities have `LocalAccount=false`, `SystemAccount=false`,
`Locked=false`, an interactive shell, safe username, and matching NSS values.
Their account types are independently verified as 0 and 1. Local positive
controls remain discoverable while remote identities are excluded.

All six real D-Bus boundaries returned `AccessDenied`: child and kiosk selecting
the remote approver; kiosk and parent selecting the remote child; the remote
child calling `GetOwnAccount`; and the remote administrator calling
`ListManagedUsers`. Preferences, limits, grants and filters across the seven
ordinary role accounts remained unchanged after every attempt.

This exposed a broker gap during code review: `_is_admin` checked only
`AccountType`, although CORE-ACCOUNTS-001 requires local administrators. It now
requires the live local-account flag too, preserving explicit root access.
A unit regression verifies locality revalidation before management reads or
writes; the real remote caller verifies installed enforcement. Existing
request failure logging supplies redacted diagnostics. Broker activation is
`process-restart`; fixture/runner changes activate on next invocation (`none`).
No host setup change or data migration is needed.
