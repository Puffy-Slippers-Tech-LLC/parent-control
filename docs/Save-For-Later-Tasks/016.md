# Check that an upgrade preserves saved time

Acceptance: installed
Targets: onpc-Ubuntu26.04-101, onpc-Fedora44-201, onpc-Fedora45-301

Prerequisite is 010. Use [migration and upgrade rules](../SystemDesign/Data-Migration.md#package-lifecycle),
the [saved-time recovery design](../Save-For-Later-Design.md#revisions-recovery-and-invalidation),
and the [installed upgrade route](../../tests/integration/README.md).

Add the planned engineering selector
`system --area package --test test_saved_grant_update` (unimplemented).
Use the maintained explicit previous/current artifact route with two distinct
verified packages of the same format. Start with a feature-bearing package
and a known valid saved record. Restart the broker and confirm exact saved
seconds and app choice. Stage a pending transition for a separate fixture
child at the controlled update boundary. Exercise the real package update,
normal activation and broker recovery in the same attempt. Verify the first
child's exact balance and app choice again, and verify that the second child's
pending result resolves once without gaining time or rewriting the original
start. Keep the engineering fixture and assertions separate from public
customer cases.

Add a second history in the same selector that starts from the newest earlier
released package, which predates the feature, prepared through the maintained
earlier-release pair route (`--upgrade-inputs`). Start with a running
immediate fixed grant and no grant store. After the real update and broker
restart, require that the grant keeps running with its original tuple, is
reported as a deadline grant that offers no Pause, and that no saved balance
appears. Then save a deferred approval and verify it is stored independently.

Run affected host fixture checks and list the exact registered selector before
live use. Run it on all declared targets, record the package identities and
actual result per target in normal runner output, and finish owned cleanup.
Reuse the maintained artifact and upgrade boundary without changing the
default historical upgrade selection.
