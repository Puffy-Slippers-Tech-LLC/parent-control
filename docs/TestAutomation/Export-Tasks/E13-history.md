# E13 — Make historical loss explicit and nonrecurring

Acceptance: host
Requires: E12

## Purpose and delivery

Deliver structured historical availability and supported recovery guidance under
the [master](../Export-Execution-Plan.md),
[proportional policy](../Export-Design.md#proportional-validation) and
[migration boundary](../Export-Design.md#compatibility-and-migration). Read E11's
remaining dispositions, delivered reference status/diagnostics and the complete
`plan_evidence_recovery` exact-authorization/queue/checkpoint transaction.

Finish E11/E12's same finite inventory using E10's revision-bound advisory policy
and existing `plan_evidence_recovery`, following the
[remaining delivery boundaries](../Export-Design.md#remaining-delivery-boundaries).
First identify what remains undelivered. If those owners already provide the
required behavior, deliver dispositions and verification without another policy
module, historical-debt database, notifier or recovery protocol.

Represent already unavailable historical proof explicitly, with the exact old
claim/identity, surviving records, missing dependencies and whether any active
consumer still requires it. Retain original test verdicts and proof-loss limits;
an old accepted summary grants no missing detailed check. Unchanged unrelated
historical debt is advisory once; changing it or depending on it revalidates
strictly. Do not hide a new missing reference behind historical status.
Where protected disclosure needs retained developer authorization, generate the
finite exact recovery proposal and preserve the pending disposition if authority
is absent. Do not ask for fabricated receipts, manually edit a checkpoint,
recreate an expired report or execute product acceptance in this plan. Apply only
already authorized exact disclosure through its controller-owned route.

## Validation and close-out

Follow the master's [mandate boundaries](../Export-Execution-Plan.md#delivery).
Reuse existing exact-authorization and disclosure-recovery checks; add only an
uncovered availability/dependency or composition boundary. Cover unchanged history
without repeated task/session failure, new bad references,
new active consumers of old missing proof, exact surviving accepted completion,
authorization mismatch, denied versus missing sources and interrupted disclosure.
Verify all migration categories now have explicit resolved or pending dispositions;
none may masquerade as passing evidence. Run scoped host recovery/document checks,
update their enduring owners and follow the master's cleanup and close-out.
