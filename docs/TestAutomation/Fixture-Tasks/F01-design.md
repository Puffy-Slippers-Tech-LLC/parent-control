# F01 — Freeze the fixture placement and consumer inventory

Acceptance: review
Requires: Baseline

## Purpose and finite scope

Freeze every current fixture family's placement and migration owner under the
[master](../Fixture-Execution-Plan.md) and [target design](../Fixture-Design.md).
This authoring does not complete the inventory or any implementation task.

## Read and deliver

Read the VM, storage, approval, support and environment owners. Inspect complete
`prepare_vm.SCRIPT_FILES` / `preparation_digest`, `baseline_guest.prepare`,
`baseline_fixtures`, `baseline_assets.py`, `native_assets.py`, builders,
artifact/named-input provenance and their system/E2E/qualification consumers.
Record each family's host-only, runtime, environment or scenario placement,
minimal guest closure, original ownership, trust actions and migration task.
Include all original baseline outputs and the retained preparation checkout.

Map every runner and alias to the seven preparation envelopes, exact shared
branch and finite harmless witness. Freeze planned public build/inspect/prune
and owned-maintenance names plus engineering selectors; names remain
unimplemented until registered. Keep offline/online, product-free/installed and
recorded serial branches explicit. Preserve all product assertions and scenario
mutation checkpoints. The initial reusable profile is native-runtime per target
ABI; guest subsets do not create build keys.

## Validation and close-out

Check every inventoried consumer has a disposition and task, with source-backed
alias mappings rather than name similarity. F51 separately freezes schemas and
safety protocols; F52 owns independent design review. Resolve inventory omissions,
check Markdown links and plan structure, and use the master's shared close-out.
No build, VM, setup or runtime policy change belongs to this review task.
