# Refresh the child countdown while the overlay stays open

Acceptance: host

Prerequisite is 001. Use the [countdown contract](../SystemDesign/Screen-Time.md#countdown-and-expiry-enforcement),
the [child panel UI API](../TestAutomation/Application-UI-API.md#child-panel),
and the [overlay lock confirmation](../Save-For-Later-Design.md#overlay-lock-confirmation).

The child extension already refreshes its estimate when the overlay process
exits. A pause or a saved approval keeps the overlay open, so the panel needs
a refresh request from the running overlay. Add that one-way request from the
overlay process to the extension's existing estimate refresh, bound to the
overlay process the extension started. The request carries no balances: the
panel rereads its usual broker source and keeps counting down usable time
only. Ignore requests from other processes or after the overlay exits, and
coalesce bursts with the existing refresh serialization. Provide the overlay
call that 012 invokes on success; do not wire it to broker actions here.

Run focused child extension and countdown checks for a refresh while the
overlay is open, a late or foreign request, rapid repeats, refresh failure and
retry, and that saved time never enters the displayed countdown. Run the
queued package check and release owned Shell and display fixtures.
