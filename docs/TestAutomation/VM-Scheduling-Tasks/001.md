# Protect unfinished runs during replacement

Acceptance: host

## Purpose and prerequisites

Prevent an upgrade from adopting unfinished ownership or silently changing saved
progress. Requires Baseline: the current checkout and preserved unrelated edits.

Read the [master](../VM-Scheduling-Design.md),
[resume/reset contract](../../../tests/README.md#resuming-test-execution),
[repair recovery](../../../tests/README.md#scripted-repair-loop),
[storage mandate](../../Mandates/Test-Storage-Mandate.md) and
[VM checkout order](../../Mandates/VM-Mandate.MD#central-vm-checkout).
Implementation routes: `tools/fix_tests_queue.py`, `tools/test_checkpoint.py`,
`tools/test_reset.py`, their discovered callers and existing shared storage.

## Finite deliverable

- Extract checkout source protection into planned `tools/test_source.py` and
  update its existing callers without changing repair policy. It owns reader
  leases, durable exclusive writer fences and a shared source generation, not
  tickets, cases, VM placement or display state. Protect startup imports, input
  preparation, execution and reload for participating host and VM tools.
  Preserve existing fence identities and recoverability during extraction.
- Keep an unfinished writer fenced through cancellation, process death and
  restart. Release requires a validated repair outcome or authorized reset;
  unrelated dirty/staged work is never evidence of repair ownership or permission
  to discard it. Generation changes must identify admitted source changes across
  independent participating runs in the checkout.
- Establish the explicit scheduling-state version/admission boundary used by
  tasks 003/004. Inspect ownership before switching implementations. Permit a
  translation only for a lossless mapping of the allowed VM selection,
  per-family accepted completions, claims, source ownership, transaction
  references and charged task admissions. Task 004's triage/admission records
  must use this boundary too; absent or stale impact decisions cannot imply `no`.
  Incompatible pipeline rounds/budgets refuse before execution or mutation.
- Refusal preserves the original records and names the original supported
  recovery route: finish old repair/Git transactions under that implementation
  before cutover, or use the existing reset contract only when abandonment is
  explicitly authorized. A compatibility reader cannot launch the old scheduler
  beside the replacement. Do not implement indefinite historical-format support.
- Document the version boundary and source-fence recovery in their existing
  owners. This task does not migrate real retained runs or authorize reset.
