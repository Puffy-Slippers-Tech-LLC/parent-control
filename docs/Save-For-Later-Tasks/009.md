# Recover interrupted transfers and clear withdrawn time

Acceptance: host

Prerequisites are 006, 007, and 008. Follow
[recovery and invalidation](../Save-For-Later-Design.md#revisions-recovery-and-invalidation),
[serialization](../Save-For-Later-Design.md#serialization-and-status-reads), and
[broker readiness](../SystemDesign/Lifecycle.md#broker-readiness).

Wire the shared per-child recovery into broker startup, pre-mutation admission,
and the bounded worker route requested by a status read. Share the existing
transaction lock and deduplicate queued recovery for each child. Persist clears
before Revoke or a control toggle, including when the later operation rolls
back. Clear invalid account records through the serialized writer and preserve
time on enabled allowance edits. Keep existing strict app and termination
behavior. Leave public method dispatch and status formatting to 010.

Use scoped concurrency and fault checks for stale clients and lost replies,
other-child Busy during a prompt, in-operation and startup recovery, a queued
read-triggered recovery, unresolved adapter outages, invalid accounts, and
revoke/toggle racing a pending intent. Verify that cleared state cannot be
replayed after rollback and that engineering probes distinguish durable state
from PAM/GDM access. Run the queued package check and release owned resources.
