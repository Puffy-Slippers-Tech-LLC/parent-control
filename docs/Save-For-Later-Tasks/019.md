# Keep a kiosk approval through reboot and use it at a fresh login

Acceptance: installed
Targets: onpc-Ubuntu26.04-101, onpc-Fedora44-201, onpc-Fedora45-301

Prerequisite is 018. Own the fresh-login variant of
[Scenario 1](../Save-For-Later-Design.md#scenario-1-approve-in-the-kiosk-save-the-combined-grant-use-it-later).
Use the [customer reboot route](../../tests/e2e/README.md#customer-reboot-observation-boundary).

Start at sign-in with zero daily time, no child desktop and no grant. From
the kiosk, save a three-minute fixed approval and verify that it creates only
a saved balance. Cancel an immediate request at the parent prompt and confirm
the prior balance. Then approve three minutes for immediate use and verify
the saved balance stays saved. Save one additional minute while that grant
is running and verify the combined balance at the transfer. Reboot normally.
Require a changed boot and unchanged saved balance. Before redemption, attempt
a fresh child password login and require the existing exhausted-time refusal:
saved time alone must not grant login. Confirm the saved balance is unchanged
by the attempt, then use saved time once.
Require the normal sign-in return and fresh child password login. The
resulting countdown reflects elapsed time since redemption. Keep the save,
reboot, redemption and login in one attempt.

Implement the planned `saved-time-reboot-fresh-login` variant using the
pending registration from 018 and record its coverage ID in this brief
before running. List and run that exact case on every declared target after
composition preflight and affected host checks. Update the recipe and
generated coverage and finish owned cleanup per target.
