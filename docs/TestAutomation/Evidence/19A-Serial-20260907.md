## Implemented contract

`graphical_serial.SerialConsole` attaches only to the lease-validated running
instance's existing `serial0`, via public
[libvirt openConsole](https://libvirt.org/html/libvirt-libvirt-domain.html#virDomainOpenConsole)
with `VIR_DOMAIN_CONSOLE_SAFE` and a
[nonblocking stream](https://libvirt.org/html/libvirt-libvirt-stream.html).
It never forces an occupied console or opens a host PTY directly. The controller
pumps bounded buffers between that stream and two inode-checked 0600 FIFOs in
its private work directory. No extra process, VM or host network listener is
created. Ownership loss revokes the stream; shutdown closes all owned resources.

The distribution registers the maintained public `virtio-terminal` console
through `add_console`. Its
[pipe interface](https://github.com/os-autoinst/os-autoinst/blob/master/consoles/virtio_terminal.pm)
also supports transports other than virtio. `GENERAL_HW_NO_SERIAL=1` still
disables the separate generalhw SOL grabber; it does not disable this console.
A fixed offline provisioning step enables the stock password-authenticated
serial getty only in the disposable attempt. It does not change the accepted
baseline, root password or product state. Development activation is `none`;
no setup dependency or saved-data migration was added.

The fixture username must match its real terminal echo and subsequent password
prompt. A separate read-only probe verifies the systemd-owned login executable,
standard argv without autologin, process/session/terminal identity, start time,
and canonical terminal mode with ECHO/ECHONL disabled. The
[standard login implementation](https://github.com/util-linux/util-linux/blob/master/login-utils/login.c)
wipes the supplied username before PAM, so argv cannot attest the account name.
The worker attests selection from the echo; the post-login observer independently
resolves the actual fixture UID and requires its sole active local serial session.

Password input uses the existing frozen secret registry and public
`type_password` with fixed options. Explicit screenshot capture stays sealed.
All raw vars, terminal data, automatic captures and worker logs remain private
and unapproved for export. Reviewed reports contain only fixed fields, digests,
counts and outcomes. The real trace shows masked password input.

After the session observation, the worker waits for the actual shell prompt.
It types `printf 'ONPC-SERIAL-%s\\n' 'OK'`; the complete output marker cannot
occur in that split command echo. The matcher tolerates terminal controls before
stdout and bounded CR/LF endings, while requiring the exact marker and newline.
The observer corroborates the session again, then verifies the greeter and
absence of unexpected sessions after real `exit`. `select_console('sut')`
returns to the graphical console. Task 19B still owns final screenshot and
three-attempt graphical qualification; this run exports no post-password image.

## Shutdown-status acceptance gap

The successful trace contains an actual backend diagnostic after the module
finished: `GENERAL_HW_IS_SHUTDOWN_CMD` truthfully returns 1 while the VM is on.
The pinned
[generalhw backend](https://github.com/os-autoinst/os-autoinst/blob/master/backend/generalhw.pm)
uses `autodie ':all'` around `system`, so that expected nonzero status throws,
despite `is_shutdown` intending to interpret it. Its cleanup then invokes the
owned poweroff callback and exits zero, with shutdown state reported as unknown.
The current `--exit-status-from-test-results` policy returns zero for the
passing module, and the outer lease independently verifies actual shutdown.

This does not invalidate the observed command or restored/off VM, but it blocks
full runner acceptance. The next slice must eliminate the diagnostic through a
supported public lifecycle operation/configuration, and ensure unexplained
backend failures cannot hide behind a module pass. Consider explicit truthful
poweroff before the final status query; do not fake an off result, patch backend
internals or loosen ownership. Then connect `runner.preflight/main` to
`ScenarioRecorder`/`EvidenceContract` and real execution.
