# Build the request and approved-time tabs

Acceptance: host

Prerequisite is 001. Use the [GUI design and drafts](../Save-For-Later-Design.md#gui-specification-and-supplied-drafts),
[shared frontend layout](../SystemDesign/Frontends.md#responsive-request-layout),
[public UI API](../TestAutomation/Application-UI-API.md), and
[localization contract](../SystemDesign/Localization.md#formatting-layout-and-accessibility).

Build the shared view in the existing request content module. Preserve the
child and approver selectors, existing inputs, window identity, responsive
frame and focus behavior. Add the title tabs, split menu, Approved time rows,
status and lock confirmation. Use stable public IDs and canonical selection
and sensitivity states. Render daily, running and saved amounts with the
existing formatting conventions. Translate new strings in all supported
languages. Validate the view via existing host UI seams before 012 connects
the live window to broker actions.

Check both surface configurations for every display state in the design,
default tab, correct approver field, Rest of the day, keyboard and Escape
behavior, default confirmation action, scaled/narrow layouts and public IDs.
Update the affected UI API inventory with the controls this task adds.
Run the queued package check and release test windows and owned display resources.
