# Connect both request screens to the timer actions

Acceptance: host

Prerequisites are 010, 011, and 025. Use the
[request flow](../Save-For-Later-Design.md#request-more-time),
[approved time states](../Save-For-Later-Design.md#other-ui-states-and-shared-behavior),
[overlay lock confirmation](../Save-For-Later-Design.md#overlay-lock-confirmation),
and [countdown contract](../SystemDesign/Screen-Time.md#countdown-and-expiry-enforcement).

Integrate the shared view into the live kiosk and overlay entry points.
Bind each async update to its target and revision, keep in-progress request
mode immutable, and distinguish loading/unavailable, busy, partial success
and recovery. Connect the approved time actions and request estimates.
Respect confirmation before an overlay pause, and show the correct outcome
when a pause fails before or after lock. Preserve kiosk return to sign-in,
the overlay's confirmation/close behavior, saved-success tab selection,
and immediate approval behavior. On each overlay success that keeps the
overlay open, invoke the panel refresh call provided by 025, and keep
countdown and admission based on usable time. Translate any new orchestration strings in all supported languages.

Run focused request UI and client checks for both surfaces:
stale child data, menu/dialog dismissal, parent cancellation, request choices,
invalid input, pending interactions, offline/older broker, lock failures,
saved and usable estimates, the refresh call on overlay success and success
navigation.
Run the queued package check and release owned UI/service fixtures.
