# Decide which faults fail a test

Acceptance: host

[Master plan](../Error_Reporting.md) · [Task queue](Task_Queue.md)

Use the qualified contract from task 001 to implement one evaluator in shared
test support. Select the qualified failure records from the surrounding log
traffic. Decode and validate each record for the owned guest, boot and case
interval. Keep the transport independent of the evaluator. Match an allowance on
the emitting component and a specific, recognized fault category. Use guest-side
occurrence order to place late records within an action window with an inclusive
start and exclusive end. Ignore exception type, message, stack, source location
and occurrence count for matching. The product assertions in the case still
establish the deliberate fault and recovery. Close the allowance before the
recovery checks begin.

Use the existing [runner verdict and repair contracts](../../../tests/README.md#scripted-repair-loop).
A valid unexpected event produces the ordinary failed case with its identity,
category and bounded diagnostic context. An unreadable or invalid required
record, including one with an unsupported format, makes observation incomplete.
Continue classifying independently readable faults. A verified unexpected fault
or independent case failure retains repair eligibility if collection also fails.
Incomplete observation on an otherwise passing case produces a visible
infrastructure blocker without starting a repair session. Carry that disposition
through case adapters, the VM queue, and the repair launcher's command-failure
fallback. After any bounded read recovery, a persistent blocker ends the
invocation after owned cleanup and leaves the case pending for explicit resume.

Use the lowest effective host checks under the
[test scope mandate](../../Mandates/Test-Scope-Mandate.md). Exercise the shared
verdict with a clean span, stale evidence, unrelated log traffic, and an allowed
category with varied details and zero or many events. During the allowance, check
the same category from a different component, a different known category from the
same component, and a readable fault with an unfamiliar or catch-all category.
Compare a late record for a fault just before the allowance closes with a fault
exactly at the closing boundary. Check malformed or unsupported required records
alone and alongside a readable unexpected fault. Check read failures with and
without an independent assertion failure.
Use the existing host repair seam to check that repair dispatch reaches its
normal session-start boundary for a real failed case and ends the invocation
without an agent or indefinite retries for a persistent observation-only
blocker. Keep scratch and diagnostics on the ordinary test storage route and
finish owned cleanup.
