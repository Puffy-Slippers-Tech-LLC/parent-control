## Change and evidence

it for an unprivileged persistent caller. In the guest's Polkit 127,
[agent registration](https://github.com/polkit-org/polkit/blob/127/src/polkitbackend/polkitbackendinteractiveauthority.c#L2738-L2745)
binds the agent to the subject user, and
[session lookup](https://github.com/polkit-org/polkit/blob/127/src/polkitbackend/polkitbackendinteractiveauthority.c#L1892-L1937)
requires the response UID to match. The root agent could register and prompt,
but responded under a different UID. The wrapper now establishes its private
controlling terminal, drops real/effective/saved credentials to the caller's
verified UID, clears inherited environment via the existing helper, then execs
the maintained `pkttyagent`. No product policy, fixture-password workaround,
host installation or baseline change was made.

The corrected case verifies deliberate wrong-password denial and unchanged
account state; valid selected-parent authentication and an actual live grant;
continued denial of AccountsService role changes and broker management methods;
and preservation of other accounts. All existing assertions were retained.
Changing the agent's execution identity cleared the shared authentication
failure. The historical exact remote error text was never retained, so the
specific historical `No session for cookie` message remains inferred from
upstream code, not an exported observation.

Denied helper responses now have fixed allowlisted session, identity, caller,
and D-Bus transport subcategories. Arbitrary terminal contents, credentials,
cookies and identities remain private in memory. The first diagnostic parser
required the helper prefix at line start and the live attempt still exported
only `authority-response`; review found prompt/control-byte residue could
precede that prefix. Matching within the same helper line fixes that limitation
and is covered by local regressions. The specific rejection subcategories have
local parser/JUnit/export verification, not a successful live rejection sample.
