## Implemented boundary

The smoke finishes its actual graphical/serial operations, disables the VNC
console through `console('sut')->disable()`, calls `power('off')`, and requires
`check_shutdown(0)` to succeed. These use the documented
[test API](https://github.com/os-autoinst/os-autoinst/blob/master/testapi.pm)
and console interface; the maintained
[VNC console](https://github.com/os-autoinst/os-autoinst/blob/master/consoles/vnc_base.pm)
closes its connection and stops polling on disable. The existing lease still
owns poweroff and checks exact domain identity. No second lifecycle owner,
fabricated off state, backend patch, new snapshot or restoration within a journey
was introduced. Status-only checking avoids `assert_shutdown`'s extra screenshot
after display revocation.

The worker uses isotovideo's normal backend exit policy, with independent existing
stage/module validation. The optional
[module-derived exit policy](https://github.com/os-autoinst/os-autoinst/blob/master/script/isotovideo)
can overwrite an earlier backend return code. Separately, any `base_state.json`
entry rejects success even after exit zero: this is the upstream
[fatal termination artifact](https://github.com/os-autoinst/os-autoinst/blob/master/bmwqemu.pm).
Presence alone is checked without reading messages or following links. Empty,
malformed, directory, FIFO and dangling-link entries also refuse. Raw files are
retained privately, never rewritten or exported as reviewed evidence.

The adapter records only fixed successful lifecycle events. Completion requires
a recorded power-on, subsequent power-off and later off observation, adapter
phase `stopped`, and a fresh `lease.guard(off=True)`. Worker reports now include
exit status, fatal-artifact presence, lifecycle events and shutdown verification.
Nonzero exit, fatal artifact, missing/failed module or stage, ownership loss and
cleanup failure remain independent reasons to fail. Test-tool activation is
`none` (next invocation); no setup, product or saved-data migration change.
