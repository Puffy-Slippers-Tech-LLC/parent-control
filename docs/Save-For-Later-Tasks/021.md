# Save, pause, and use approved time from the child overlay

Acceptance: installed
Targets: onpc-Ubuntu26.04-101, onpc-Fedora44-201, onpc-Fedora45-301

Prerequisite is 017. Own [Scenario 3](../Save-For-Later-Design.md#scenario-3-pause-save-and-use-time-from-the-child-overlay).
Follow the [app-policy rules](../Save-For-Later-Design.md#app-policy-revocation-and-other-lifecycle-operations)
and [E2E implementation route](../../tests/e2e/README.md#verify-edits).

With zero daily time and an overlay-approved fixed grant, confirm Pause,
observe the lock and exhausted shield, and return via kiosk redemption and
ordinary password unlock. Then establish the scenario's 30 minutes of daily
time and no running grant using public controls. Save 15 minutes from the
overlay without locking. Before Use saved time, change one of the approved
soft apps to hard blocked in Parent and leave one soft. Redeem while daily
time is usable and require the immediate countdown increase and overlay
closure. Check the two apps through existing normal launch routes to verify
the stored choice and current policy. With a fixed grant running, defer one
additional minute and confirm the lock. Require daily-only access on
password unlock and verify the saved balance after the transfer boundary.
Submit one immediate approval in the overlay and confirm the saved balance
stays saved. Keep each observation within the same installed attempt.

Register the planned `saved-time-child-overlay` variant as its own scenario
with a new coverage ID. Record the numeric selector in this brief before
running. Run after preflight and affected host checks on each declared target.
Use separate host/engineering checks for injected failures. Update recipe
and coverage and finish owned cleanup per target.
