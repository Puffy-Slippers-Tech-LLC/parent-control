# E03p-capture — Publish and acknowledge working capture

Acceptance: host
Requires: E03p-auth

## Delivery

Follow the [master](../Export-Execution-Plan.md) and
[capture contract](../Export-Design.md#capture-and-publication). Read complete
bundle export/verification, owner-local capture state, retention publication/
recovery, plan capture/carry and authenticated helper dispatch, including callers.

Publish E03p-auth's exact sealed selection with the existing independent verified
bundle transaction. Keep the request and resulting receipt in its owning workflow
journal. Record source acknowledgement only after independently verifying the
destination, complete member closure, request, attempt and source identities.
Publish any matching locator before older destination generations retire.

Reuse existing preparing/committed recovery and the same registered stage after
interruption. Owner-local pending records guard required originals at every
retirement route before production capture activates. Do not build a global
consumer catalogue, capacity-reservation database, retirement-permit protocol,
segmented writer or second working index. Registered inspection stays compatible;
add only the bounded helper capability necessary for publication/acknowledgement.

## Acceptance

P03/P12 use private stores with real seal, publication, verification and recovery
functions. Cover interrupted seal/copy/commit/locator/ack, lost replies, stale
attempt/request/closure, changed or missing source/destination, denied authority
and cancellation. Retry the same intent without extra slots or session allowance.
A receipt JSON alone never releases a source or supplies a pass.

Preflight old + sealed + staging + committed-unretired + control/recovery usage
within existing byte/file/metadata limits; compare actual use before commit.
Capacity or verification failure preserves the required source and previous proof.
Before enabling callers, test pending-source refusal at direct count removal,
prune, host/privileged reconcile (including the separate privileged prune),
publication/explicit retirement and other applicable routes in the
[retirement inventory](../Export-Design.md#retirement-entry-points).
Successful verified acknowledgement releases only the exact recorded source;
unreferenced disposable controls retain their existing cleanup.

Use the master's scoped host checks, explicit timeouts, controller-source guards,
applicable resource review, changed-link checks and owned cleanup. Register any
new interface and concrete selectors before invocation. E03 still owns real
continuation, suspension and restart composition; this row does not complete it.
