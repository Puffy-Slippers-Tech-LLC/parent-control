# Start saved time once with the approved app access

Acceptance: host

Prerequisites are 003 and 005. Follow the [redemption protocol](../Save-For-Later-Design.md#use-saved-time),
[usage source rules](../Save-For-Later-Design.md#sources-of-d), and
[broker approval effects](../SystemDesign/Broker.md#authorization-and-grant-transactions).

Implement a single redemption transition for both surfaces. Start the entire
positive saved balance at the accepted time, combine it with the larger of
daily and active time, and apply the stored choice against current app policy
through the existing approval effect path. Journal entry into termination
before signaling processes. Recover using the exact target tuple and original
start timestamp. Resolve each live-tuple branch, including external replacement,
and preserve deadline classification when a contributing deadline grant is
absorbed. The transition handles its own pending intent. Public wiring is later.

Use focused tests for stale/repeated actions, zero balance, overflow and both
usage sources; both soft choices, hard blocks, a changed parent policy and
other-child isolation; pre-intent failures, failed/late writes, write/read-back
uncertainty, failed roll-forward and long downtime. Verify that a recovery
never duplicates the balance or restarts the elapsed grant and respects prior
time and irreversible app effects where the approval contract requires it.
Run the queued package check and release owned resources.
