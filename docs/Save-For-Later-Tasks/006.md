# Pause the timer and preserve the remaining approved time

Acceptance: host

Prerequisites are 003 and 005. Follow the [pause protocol](../Save-For-Later-Design.md#the-pause-step)
and [app-policy rules](../Save-For-Later-Design.md#app-policy-revocation-and-other-lifecycle-operations).

Implement the serialized pause transition for both caller rules. Recheck the
revision and live fixed tuple before locking, capture completed usage after
lock, and use the shared transfer boundary B for accounting and the shortened
tuple. Persist the intent before the bounded verified AccountsService write.
Resolve every live-tuple outcome from the pause recovery table. Retain the prior
saved app choice when a balance already exists. Treat a matching pause-ended
tuple as expired in PrepareOwnSession, including an unlock before B. The
transition handles its own pending intent. Startup and public status wiring
belong to later tasks.

Use focused transfer checks for exact-second conservation with zero and
positive D, X = 0, wrong mode, stale revision, failed lock or capture, the
bounded early-unlock window, partial store writes, timeout and read-back
before/after B, external replacement, and restart after each durable boundary.
Confirm that a pause has no immediate app effect, with strict policy restored
on session entry. Run the queued package check and release owned resources.
