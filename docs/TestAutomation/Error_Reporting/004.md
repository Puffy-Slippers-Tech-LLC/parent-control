# Verify that unexpected faults reach repair

Acceptance: installed
Targets: onpc-Ubuntu26.04

[Master plan](../Error_Reporting.md) · [Task queue](Task_Queue.md)

Verify the integrated verdict and exact-case repair handoff on current product
code using the [installed engineering route](../../../tests/integration/README.md#running-the-current-installed-suite)
and the [repair contract](../../../tests/README.md#scripted-repair-loop).
Exercise only the acceptance gaps left after tasks 001–003. Run E2E case `120`
as the healthy reboot control and verify that its verdict accounts for both
boots. Use a bounded installed engineering qualification for a deliberate
outage with proven recovery, an unexpected report-triggering fault, a log-only
fault, and a repetition of the allowed category after the allowance closes.
Reuse the guarded emission route from task 001. Through the runner's supported
reboot path, observe actual fault records late in the departing boot and during
startup of the next boot before guest transport readiness. Verify that both
belong to the same case and that a fault on either edge can veto the pass. In
each unexpected-fault variant, all other case assertions should pass so the
final verdict proves that error detection prevents the false pass. Follow the
[test scope mandate](../../Mandates/Test-Scope-Mandate.md) and preserve customer
journeys as public acceptance.

Verify that an installed negative produces the exact failed case, VM selector
and structured fault context and carries them to the ordinary repair dispatch
after owned cleanup. Use focused host checks to verify that each of the three
runner adapters publishes a terminal failure with the exact case and context.
Carry an observation-only blocker through each adapter, the VM queue and
`fix-tests`, including the standalone check's nonzero command result. Verify
that the invocation ends with the case pending and zero session-start requests
or automatic reattempts. Use the maintained host repair seam with a substitute
for model execution. Healthy and expected-fault passes also produce zero
session-start requests. Keep diagnostics in the existing result artifacts.
Finish owned cleanup and report the result for the named target.
